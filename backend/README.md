# Backend 문제 풀이 트랙

FastAPI와 PostgreSQL로 백엔드 프로젝트 구현력을 기르는 실습 모음입니다.
각 과제는 독립된 폴더이며, `README.md`의 요구사항을 읽고 `TODO`를 구현한 뒤
테스트로 결과를 확인합니다.

## 학습 방식

1. 과제 폴더의 `README.md`만 먼저 읽습니다.
2. `rg TODO`로 구현할 위치를 확인합니다.
3. 테스트 이름을 보고 필요한 동작을 추론합니다.
4. 한 번에 하나씩 구현하고 `pytest`를 실행합니다.
5. 테스트가 모두 통과하면 리팩터링합니다.

정답 코드는 제공하지 않습니다. 막힌 경우에는 오류 메시지와 시도한 내용을
바탕으로 힌트를 단계별로 요청하세요.

## 커리큘럼

| 번호 | 주제 | 핵심 역량 | 저장소 |
|---|---|---|---|
| 01 | FastAPI 첫 CRUD | 라우팅, 상태 코드, Pydantic 검증 | 메모리 |
| 02 | 계층 분리 | router/service/repository, 의존성 주입 | 메모리 |
| 03 | PostgreSQL 연결 | Docker Compose, SQLAlchemy, 세션 | PostgreSQL |
| 04 | 사용자 CRUD | 마이그레이션, 유일성, 예외 처리 | PostgreSQL |
| 05 | 인증 | 비밀번호 해시, JWT, 권한 | PostgreSQL |
| 06 | 게시글 API | 관계, 페이지네이션, 검색 | PostgreSQL |
| 07 | 테스트 가능한 설계 | fixture, 테스트 DB, 트랜잭션 격리 | PostgreSQL |
| 08 | 동시성·정합성 | 트랜잭션, 잠금, 재고 차감 | PostgreSQL |
| 09 | 운영 기초 | 설정 분리, 로깅, 헬스 체크 | PostgreSQL |
| 10 | 미니 프로젝트 | 요구사항 분석부터 배포 구성까지 | PostgreSQL |

현재 제공된 과제부터 순서대로 진행합니다. 뒤 과제는 앞 과제를 완료한 뒤
난이도와 취약점을 반영해 추가합니다.

## 공통 원칙

- Python 3.11 이상을 사용합니다.
- API 오류는 의미 있는 HTTP 상태 코드와 응답 본문으로 표현합니다.
- 구현 완료 기준은 테스트 통과뿐 아니라 타입과 이름이 의도를 드러내는 것입니다.
- 과제 폴더끼리 코드를 import하지 않습니다.
