# Study with AI

백엔드, DevOps, ML Engineering, MLOps를 기초부터 운영 수준까지 장기적으로
학습하는 문제 풀이 저장소입니다. 커리큘럼은 10개 과제로 끝나는 고정 목록이
아니며, 학습 결과와 기술 변화에 따라 계속 확장합니다.

## 트랙 구조

```text
study-with-ai/
├── backend/                 API, 데이터베이스, 보안, 분산 시스템
├── devops/                  Linux, 컨테이너, CI/CD, Kubernetes, IaC, SRE
├── ml-engineering/
│   ├── data-engineering/    데이터 수집·검증·저장·분산 처리
│   ├── machine-learning/    전통 ML 알고리즘과 평가
│   ├── deep-learning/       신경망 기초부터 Transformer까지
│   └── ml-systems/          학습·추론 시스템과 성능
└── mlops/                   실험·버전·파이프라인·배포·모니터링
```

각 트랙 README에는 장기 로드맵을 기록하고, 실제 과제 폴더는 하나씩
추가합니다. 따라서 로드맵에 있는 모든 폴더가 처음부터 존재하지는 않습니다.

## 공통 학습 원칙

1. 한 번에 한 과제만 진행합니다.
2. 과제 README에서 개념, 요구사항, 제약, 완료 조건을 먼저 읽습니다.
3. 작은 테스트부터 통과시키고 실제 실행 환경에서도 확인합니다.
4. 테스트 통과 후 왜 동작하는지 설명하고 리팩터링합니다.
5. 완료 후 질문에 답하고 어려웠던 부분을 기록합니다.
6. 다음 과제는 이전 결과를 토대로 난이도와 범위를 조정합니다.

각 과제는 가능한 한 다음 요소를 포함합니다.

- 선수 지식과 학습 목표
- 핵심 개념 설명과 참고 키워드
- 작게 나눈 구현 요구사항
- `TODO`가 있는 시작 코드 또는 설정
- 정상·경계·실패 사례 자동 테스트
- 실제 실행 및 관찰 방법
- 완료 후 복습 질문과 확장 실습

## 권장 학습 순서

모든 트랙을 끝낸 뒤 다음 트랙으로 넘어갈 필요는 없습니다. 기초 구간을
맞춰 병행하는 편이 좋습니다.

```text
Backend 기초 ────────────────┐
                             ├─> 서비스 프로젝트 ─> MLOps/운영 통합
DevOps Docker·Linux ─────────┤
                             │
Data Engineering ─> ML ─> DL┘
                         │
                         └────> ML Systems ─> MLOps
```

권장 시작 순서는 다음과 같습니다.

1. Backend 01~03과 DevOps 01~07로 애플리케이션·데이터베이스·운영 기초 학습
2. Data Engineering 기초와 Machine Learning 수학·회귀·분류 학습
3. Deep Learning과 ML Systems 시작
4. 재현 가능한 모델이 생기면 MLOps 실험 추적과 버전 관리 시작
5. 이후 각 트랙을 프로젝트 요구에 맞게 교차 진행

## 커리큘럼 운영 방식

- 번호는 권장 학습 순서를 나타내며 실력에 따라 일부를 병행할 수 있습니다.
- 이미 제공된 과제 번호와 경로는 가능한 한 유지합니다.
- 새로운 기초 단계가 필요하면 보충 과제(`05a` 등)를 추가할 수 있습니다.
- 새로운 기술을 무조건 추가하지 않고, 변하지 않는 원리와 운영 판단을 먼저
  학습합니다.
- 큰 프로젝트는 여러 단계의 작은 과제로 나누며 중간 결과를 계속 검증합니다.
- 각 트랙의 마지막 번호는 종착점이 아니라 다음 확장의 출발점입니다.
